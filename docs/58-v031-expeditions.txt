TankStorm v0.31.0 — 指挥官属性、采集入库与分类档案
构建日期：2026-10-04

本轮修改

1. 先手和二次开火归属指挥官，不再按六组战车平均，也不再包含兵阶加成。
   先手 = 100 + 机动科技×3 + 战场预判技能×3。
   二次开火 = 100 + 精密弹道科技×4 + 连击指挥技能×4。
   先手高者先攻，同值进攻方先攻；每次正常行动后追加开火概率为10%+(己方值-敌方值)×0.1个百分点，限制在0%—35%。
   连击仍只追加一次，使用50%攻击力，随后正常进行命中、暴击、克制等判定。
   保留技能/科技原系数，只去除车辆归属和兵阶影响；敌方按关卡/据点的指挥科技生成属性。
   属性与战力页面采用同一个指挥官来源；单车战力中的相关分数是分摊贡献，不表示车辆拥有这些属性。
   新远征保存出发时的指挥官快照。旧在途远征继续使用旧快照；历史战报的事件、伤害和结果不重算。

2. 世界战前标题右侧明确显示“本次总运力”，点击打开行动计划。
   原先挤在预设下方的运力不再是唯一入口；世界目标详情也突出运力。

3. 采集归队新增独立入库收据。
   本次排查确认：原源码已有返城资源加账逻辑，缺少统一战报列表的归队记录；未复现仓容充足时的资源丢失。
   现通过同一事件结算记录带回、实际入库、溢出丢弃、生还、待修和永久损失。
   每类采集资源实际入库=min(带回数量,max(0,归队当时容量-库存))；其余丢弃。
   归队之前自产可能占用仓容，按实际到达时的剩余量计算。已拥有的超仓资源不削减。
   本次只调整采集归队的容量规则；关卡奖励、据点突袭战利品和退款保持原先可超仓规则。
   8小时休整与逐分钟推进使用同一流程；收据、读档、历史回放都不再次发奖。
   无守军采集、失败远征和中途召回均有独立记录；完全战败显示失败，零物资明确显示0。

4. 战地档案统一保留最近400条，战斗与归队共同占用此额度，按结算时间排序。
   类型包含主线副本、核心副本、资源点进攻、据点突袭、采集归队、突袭归队、演习。
   可按类型和成功/失败组合筛选；未知来源的旧世界战斗保留为“世界战斗”，不猜测类型。
   胜利/成功归队用绿色，失败用橙红，同时提供文字；矿点进攻与最终入库明确分开。
   归队收据可查看关联战斗；若战斗已超过保留数量，则不能再回放。收据仍保留其自身损失快照。
   新记录通过刷新接入，避免列表移动导致误点；归队也点亮新战报标记。
   存档导入上限由20MB扩至256MB，容纳更长档案；未对400场全部达到事件上限的极端文件进行压力测试。

5. 主界面左上角显示v0.31.0和构建日期，窗口标题同步。
   打包脚本按新加坡时区写入日期，支持SOURCE_DATE_EPOCH，EXE文件/产品版本同步0.31.0.0。

关键文件
src/core/archive.ts：混合档案、类型和400条保留策略。
src/core/engine.ts、types.ts、validate.ts、overview.ts：入库拆分、远征与历史兼容。
src/core/battle.ts、power.ts、attributes.ts：指挥官属性、快照和战力口径。
native/rules/bridge.ts、native/scripts/game.gd：运力、收据、筛选、通知、版本和原生验收。
src/core/library.ts、native/PLAYER_GUIDE.txt：现行规则。
tests/expeditions-v31.test.ts、tests/native.test.ts、native/tests/expeditions31.mjs：专项验证。

验证
1. npm test -- --maxWorkers=2：35个测试文件，595项通过。
   包括仓容充足/部分空余/已满/旧超仓、8小时与逐分钟一致、召回、失败、历史快照、扣费幂等、旧存档与400条混合保留。
2. npm run check：TypeScript和Prettier通过；Godot语法检查与Windows导出通过。
3. 原生隔离存档验收V31_EXPEDITIONS_QA=true：真实点击流程进入世界战前、休整确认、归队、筛选、收据与回放。
   样例采集带回19,200铁矿：有仓容实际入库19,200；满仓实际入库0、丢弃19,200。
   6类筛选和失败筛选有效；回放前后库存、档案和收据保持一致。
4. 1180×680、1280×720、1920×1080、2560×1440，各100%与120%字号，另检查全屏。
   截图核对战前运力、分类档案和归队弹窗；零入库不留空白，小窗口按钮无裁切。
5. 全部验收使用新建smoke存档，不读取或编辑玩家主存档。桌面工具查看了原生窗口；交互回归使用Godot内输入事件驱动。

发布与兼容
公开发布v0.31.0；本次提交也纳入此前v0.26—v0.30已完成的本地更新，细节见docs/51至57。
保留旧存档、订单费用/工期快照、既有车辆、关卡领取记录。未对无法确认的旧采集收益追补或重复发放。
旧报告只保证仍留在存档中的内容可读，已经被旧100条上限清除的历史无法恢复。
Windows免安装包及SHA256作为GitHub Release附件；EXE、运行时、打包程序、测试存档不进入Git。
