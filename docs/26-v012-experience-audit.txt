TankStorm v0.12.0 — 体验优化、指挥台 UI 与美术整合
验收日期：2026-10-03

一、以实际源码为基线
本轮从 v0.11.0 工作区继续，保留原有尚未提交的 v0.8—v0.11 改动。
工程为 Godot 4.6.2 原生 Control 绘制、1600×900 逻辑画布、本机 TypeScript 规则桥接。
规则进程生成同一份 state 和衍生 info，客户端定期接收并重绘；结算发生在规则层，
回放只消费报告的 initial / final / events / actions 快照。
存档沿用现有校验和、备份、独立副本与迁移机制；没有修改真实玩家存档进行测试。

审计描述与当前基线的差异：
- 资源一览、战后结算、跳过进入结算、三厂就地升级、21 项树状科研已实现，本轮验证并扩展。
- “工厂 42 / 编队 142”在当前快照投影中未复现；新增完成时原生流程与桥接一致性断言，
  并补充完成通知、导航圆点以及单辆制造 / 维修完成通知。不是根据截图臆测库存丢失。
- 普通核心副本首胜 10、重复 3 为已有规则，本轮保留并回归八种核心副本。
- 弹窗之前已有归零代码，但复用布局可能覆盖归零时机；本轮按标题+内容保存独立位置，
  新文档延后至布局完成归零，同内容恢复阅读位置，并用两个内容实际切换验证。
- 历史世界报告的“待运输 / 已入库”原先缺少可靠依据；本轮增加真实归队凭据，
  不再仅因当前行军不存在而推定旧报告已经到账。

二、状态与结算
新增可选 expeditionLog：marchId、targetId、at、outcome、cargo、survivors，最多 100 条。
实际归队在资源和生还车辆入库时写入，部队全损写 defeated；重复推进不重复入库。
旧存档没有此字段也可读取。没有凭据且不在行军中的旧报告显示“历史装运记录”，
不能恢复缺失的历史实际入库量，也不会补发、回滚或重算旧奖励。

transportStatus 是只读投影：区分前往、采集、返程、归队、全损、历史未知。
报告原始 rewards 不变；世界结算页和列表按在途货物 / 归队 cargo 显示实际运输数，
详细报告保留战时缴获。当前打开的报告随状态轮询更新运输标签。
战报列表优先展示核心图标和数量；所有奖励仍以规则层保存的报告为准。
有效伤害按生命差统计，新增逐阵位承伤，避免把致死溢出当成实际伤害。
失败建议基于前排损失、敌军剩余生命、先手和新规则下的克制命中比例。
结果页提供维修、编队、科研、重试、奖励用途、战报等入口。

休整摘要记录资源净变化、完成建设 / 研究、制造、改装、维修、归队和新战斗。
制造数排除改装目标，改装单独统计；完整记录可展开。该摘要属于当前会话反馈，
再次启动可查看持久化通知和战报，但不恢复上次未关闭的休整摘要页面。

三、UI 与美术
共享 Theme 统一普通弹窗、输入框、按钮、正常 / 悬停 / 按下 / 聚焦 / 禁用状态。
主界面继续使用深墨绿、枪灰、黄铜；友军绿色、敌军与危险暖红，并有文字标识。
增加 Tab / Shift+Tab 焦点、Enter 执行、音量、窗口模式、正文 100% / 110% 缩放。
整体画布依窗口按比例适配；本次没有增加自由拖动布局或任意比例 UI 缩放。
高级设置集中 JSON、备份、诊断与本机 root；正常设置保留保存、复制、切换、音量和帮助。
禁用动作显示所需建筑 / 前置科技、资源缺口、队列或维修状态，点击可进入相关页面。

保留现有 28 种战车及双方朝向图集，统一绘制基准、接地阴影和阶级体量。
启用战车、残骸和组件图标 mipmaps，改善小尺寸缩小时的锯齿与细节噪声。
新增 8 张军械组件核心图片，四车系分别采用装甲环、穿甲 / 观瞄、炮闩液压、火箭组件，
VI / VII 使用不同图片与角标。VII 新图使用 *_core7_field 文件名，保留旧图便于历史对照。
新增 4 张工业 / 油田 / 要塞 / 试验场地表，按报告任务身份选择，压低背景亮度与干扰。
生成素材未经脚本裁剪或重绘；提示、参考图和文件对应见 27、28、29 号 provenance JSON。
截图复查后，坦克 VII 改为多面装甲传感器模块，火箭 VII 改为六格方形发射组件，
进一步区分 VI 的平面装甲环和双管火箭组件；最终两个提示以 29 号记录为准。
这次属于资产整合和展示统一，没有再次重绘全部 28 种战车。

战场保留中央折叠、沿行军轴的微动、逐发射击和四车系独立声效。
扩大阵位间距；残骸先画，存活战车后画，生命 / 数量标签最后画。
残骸仍随地面移动，在接近边界时退出显示，不会固定在屏幕或拖到按钮下面。
标签避让并限制可视边界；缩小爆炸，补充阵位、生命条、行动者和目标高亮。
新增 N / “逐次攻击”：暂停并推进完整行动，包含该行动的连续多发，不重新模拟。

四、决策、养成与地图
编队卡：实际单车攻击 / 生命、总生命、载重、数量、攻击模式及克制。
库存：车系、阶级、待命 / 全部 / 待修、数量排序；候选先预览，再确认替换当前阵位。
对比：替换前后火力、承伤、载重；六格图解同时展示完整前排与前排清空后的目标。
库存口径明确：现有总量 = 待命 + 出征 + 待修 + 维修中 + 改装原车；
编队只是分配计划，未完成目标车辆单列待产，不能重复加入现有库存。

世界行动增加与战役同样的战前确认，原子校验选定阵型后再预留车辆。
敌军预览只读取保存的侦察，未知保持未知，超过刷新周期明确标记过期。
显示己方与已知敌方总生命、先手和二次开火；生命比较不等于预测胜率。
地图增加资源 / 据点、等级段、情报筛选和图例；放大后展示标签，限制边界外标签。
显示队伍编号、目标坐标、路线、前往 / 采集 / 返回阶段；下一队计划与活动队伍分开。
计划采集量、载重、采速、分段时间和预计归队均使用现有报价 / 行军快照。
归队记录展示货物、生还和对应报告的当时待修 / 永久损失，避免把历史待修当当前库存。
支持直接应用编队预设；没有新增自由命名远征队伍的持久字段。

建筑可查看升级收益与后续解锁；改装使用原车 → 目标卡片和总成本 / 时间详情。
工厂当前任务下显示下一批任务及预计完成倒计时；调度中心列出全部等待项目。
通关后提示核心获取 → 高阶制造 / 改装 → 编队 → 精英挑战的现有成长路线。
时间设计不变：休整推进整个单机世界，VIP 免费完成符合阈值的非行军项目，
金币加速处理指定作业；旧任务下单成本 / 速度快照、VIP 队列 FIFO 和在途运力均保留。

五、改动位置
src/core/overview.ts：运输投影、休整摘要、伤害 / 承伤与战后建议。

native/scripts/game.gd：主题、交互、页面、回放、地图、设置和原生验收。
native/assets：核心、地表及导入参数；已有战车资源不替换。
tests/experience.test.ts：9 项新增状态 / 历史 / 库存 / 队列 / 兼容检查。
native/tests/fixtures.mjs：独立原生验收场景和快照。
package*.json、native/export_presets.cfg、README.md、PLAYER_GUIDE.txt：v0.12.0 交付。
