# 经典战线首版实现与使用说明

2026 年 10 月 2 日，项目已从研究资料进入可运行的单人版本。当前实现覆盖 M1 的基地、造兵、六格战斗、世界采运、战损修复和存档闭环；多人账号、真实 PvP、军团与协防属于后续 M2。本文件描述已写入代码的行为，历史证据仍以 01 至 11 号研究文档为准。

## 启动与构建

本机已经安装依赖。双击仓库根目录 `start-game.cmd`，或在项目目录运行：

```powershell
npm ci
npm run dev
```

浏览器打开 `http://127.0.0.1:5173/`。首次运行时填写指挥官名称和世界种子，建立新档案。后续自动恢复上次档案。需要 Node.js 22.12 或以上；本次实际环境为 Node.js 24.14.1。

```powershell
npm test                 # 规则、经济、存档与耐久测试
npm run test:report      # 将执行结果写入 artifacts/test-results.json
npm run check           # TypeScript 与代码格式检查
npm run build           # 产物写入 dist/
npm run preview         # 预览生产构建，默认端口 4173
```

开发服务器只绑定本机地址。停止终端中的服务后页面无法重新加载，再运行启动脚本即可。已加载的单人游戏不需要互联网账号。不同浏览器、域名和端口各自拥有本地存档；例如 `localhost`、`127.0.0.1`、5173 和 4173 之间应通过导出、导入迁移。

## 第一轮游玩

1. 打开“成长任务”，领取归队补给。初始拥有坦克 20、歼击车 8、自行火炮 6、火箭车 6；赠送部队是复刻版的入门设计。
2. 点击基地上的指挥中心开始升级。建筑、科研、生产和修理各有一条独立队列。
3. 在军备工厂生产 10 辆轻型坦克。每完成一辆立即入库；取消只取消尚未完成的部分。
4. 在作战编队中分配六格。可选择兵种、填写数量、撤下或交换位置；点“保存编队”后才应用到出征。单格初始上限 20 辆。
5. 经典战役的“战术演习”没有兵力和奖励变化。正式出击会产生真实战损；动画可暂停、倍速、跳过和重放。
6. 在世界地图侦察基地右侧 `(17,16)` 的铁矿。第一批近郊矿点没有守军；出征、采集与返航都有独立阶段。每小时基础采集 300 份，装满自动返回；也可以带着已有货物提前召回。
7. 战斗损失分为待修和永久损失。到军备工厂的修复中心安排修理，完成后战车重新可用。
8. 设置与存档中可以改名、创建独立档案、导出 JSON、导入 JSON。导入总是创建新档案，不覆盖原档案。

桌面右侧显示“基地动态”。小屏点击顶部无线电图标打开同样的队列与行军操作。表单可用 Tab、Enter 操作，Esc 关闭弹窗。

## 已实现的内容

| 系统 | 当前行为 |
| --- | --- |
| 建筑 | 指挥中心、工厂、科研、仓库、五种资源设施，共 9 类；最高 20 级 |
| 资源 | 铁、油、铅、钛、水晶和任务金币；显示产率与自然产出上限；外来收益允许超仓 |
| 战车 | 四类兵种各三代，共 12 个型号；数量库存、待修、修复中、出征和损毁分别记录 |
| 科技 | 火控、装甲、装配、工程、后勤五条研究线；生产时长和出征战斗属性在任务开始时锁定 |
| 编队 | 六格、逐格数量、库存校验、换位、填充、最多五个预设；预设不占用库存 |
| 战役 | 十二个自拟战役；顺序解锁、首通与重复奖励、无损演习、战损、成长奖励、完整事件回放 |
| 世界 | 32 × 32 坐标地图、100 个有限储量矿点或 NPC 据点、侦察快照、两支远征队列、运输载重 |
| NPC | 有限守军和有限钱包；被攻击后保留实际残余兵力；每种资源保护 1000 份；不会无限刷新资产 |
| 指挥官 | 经验等级、确定性统率、声望军衔、攻击技能、北京时间每日补给 |
| 保存 | IndexedDB 事务、命令幂等、修订号检查、后台 Worker、最近一次提交前备份、校验导入导出 |
| 美术与音效 | 原创军事基地背景，四类 SVG 战车，军绿钢铁界面；可选合成战斗音效，默认关闭 |

## 代码与扩展入口

```text
src/core/types.ts          世界、编队、战报和命令契约
src/core/content.ts        名称、建筑整数表、科技、关卡、奖励和任务
src/core/battle.ts         纯战斗函数、固定种子随机数与伤亡汇总
src/core/engine.ts         经济、队列、世界事件、命令和守恒断言
src/core/validate.ts       存档各级对象的结构与范围校验
src/core/storage.ts        IndexedDB 原子事务、备份、导出与导入
src/client/game.worker.ts  在后台执行读档、推进、命令与保存
src/client/local.ts        UI 与 Worker 的请求适配器
src/client/diagnostics.ts  开发模式性能采样，不读取或记录玩家档案
src/ui/                    页面、战斗播放、表单、原创矢量战车和样式
design/                    原型规则与兵种配置
public/art/                基地图片及生成来源、完整提示词清单
tests/                     可重复运行的自动化测试
artifacts/                 已执行测试报告、性能数据及界面截图
```

界面不重新计算伤害或发放战利品。战斗核心先产生完整事件流，事务提交库存、伤残和奖励后，界面播放已经确定的结果。关闭回放不会取消战损。世界战报中的货物表示装载量，只有回城时加入钱包。

Worker 在 IndexedDB 的 readwrite 事务内同步读取、计算和写入；事务期间不等待网络或图片。浏览器的事务串行保证多个页面不会用同一份旧库存各自出兵。命令收据随状态提交，同 ID 同内容重试只返回既有结果。主线程负责操作与显示。

存档采用 schema 1 与 `classic-prototype-v0.1` 规则标识。SHA-256 用于识别损坏，并非防作弊签名；导入还会检查字段结构、引用、数值范围与兵力守恒。当前不承诺未知版本自动迁移，无法识别的版本会明确拒绝。

## 与准备设计的具体取舍

- 本版使用 React、DOM、CSS 和 SVG 渲染场景与战车；研究阶段提出的 PixiJS 是候选技术，并未安装。业务核心保持 TypeScript 纯函数，后台执行采用原计划的 Worker。
- 建筑费用使用已提交的整数分档表，生产、科技、兵种属性分别位于内容表和原型规则文件。后续调平应同时更新规则标识、测试和说明，不应把改过的数值解释为历史原版。
- 六格编号、光环、取整、暴击、命中、修复比例和十二关守军都采用准备文档中的建议规则或明确的自拟补全；本版不声称还原原服务端的精确数据。
- 游戏初始世界是确定的有限世界。矿点不再生，NPC 不主动侵略或经营。资源建筑的长期生产仍可维持基地。
- 旧战报保留最近 100 场。每次事务前保存一份自动备份，当前主档与备份形成两个可恢复状态；常规跨设备备份使用导出文件。
- 生成图片由内置 imagegen 完成，保存到 `public/art/base.png`；完整提示词和来源位于 `public/art/manifest.json`。没有把原游戏客户端图片作为运行资产。

## 后续迭代边界

下一阶段可优先进行长线成长调平、矿点刷新策略、更多地图地形与战斗动画，以及根据用户记忆校准建筑布局。军团、聊天、真人 PvP、账号服务端、协防和迁城尚未实现；必须按照 M2 的多人事务和权限标准另行开发验收。

当前测试证明有限范围内的规则正确性和可操作性。长期玩家体验、多个实体移动设备的性能、原版数值一致性仍需要后续验证，不能由自动化通过推导为已经完成。
