# 坦克风云经典界面与美术参考

本文件给后续制作定义界面流程和资产范围。早期攻略提供工厂、资源、编队、战斗和指挥官的参考画面入口；精确像素、字号和布局尚未逐图标定。本轮 UI 尺寸与视觉风格是设计建议。

## 参考入口与使用方式

[2014 年新手攻略 S06](https://news.4399.com/gonglue/tkfy/xinde/m/370500.html)中依次包含工厂、郊外资源、战前编队、自动战斗与指挥官配图，是后续核对早期视觉的首选。官网与 TapTap 的截图更可能包含后期系统，使用前标记年代，不直接作为早期完整布局。[官网 S01](https://tk.rayjoy.com/)，[产品页 S04](https://www.taptap.cn/app/35038)。

这些入口是研究参考，尚未建立原图本地档案或完成所有图片的视觉比对。后续可以人工标注画面区域、阵位朝向、单位名称和按钮功能。游戏成品资产采用原创重绘或有明确许可的素材，不把检索图片直接放进发布包。

## 全局信息结构

顶栏展示五资源，紧凑模式显示整数或 K/M 缩写，展开后给准确数量、容量和产率。金币与五资源分开。右侧或底部展示建筑、研究、生产、修理与行军状态，任何倒计时都有完成时间和业务名称。

主导航建议为基地、世界、关卡、部队、指挥官、战报。军团在单人模式显示未来扩展说明或隐藏，不以不可点击付费按钮占主要位置。PC 使用侧栏，竖屏使用底栏；内容名称与含义保持相同。

## 核心界面详细设计

| 页面 | 必须显示 | 主要交互与异常 |
| --- | --- | --- |
| 基地 | 指挥中心等级、建筑、资源土地、活动队列 | 点击建筑进入详情；不能依靠小图标记忆唯一入口 |
| 建筑详情 | 当前效果、下级效果、费用、时长、前置 | 缺资源、等级受限、队列忙各有明确原因 |
| 工厂 | 单位型号、代际、攻击、生命、载重、费用、制造速度 | 数量输入、最大可生产、提交前总成本，解锁条件可见 |
| 库存 | 每型可用、出征、待修与累计损失 | 快速进入造兵、编队和修理，不合并成一个误导总数 |
| 科技 | 等级、效果、前置和研究队列 | 选择科技后对比下级，不只显示“战力上升” |
| 指挥官 | 等级、经验、每格带兵、统率、声望、技能 | 显示下一成长的作用和材料来源 |
| 编队 | 两排六格、型号、数量、每格上限、剩余库存 | 点选与交换，数字输入，清空，满编，保存预设 |
| 出征确认 | 目标、情报时刻、距离、预计到达、投入、载重、费用 | 正式战斗说明可能损失部队；明确确认与取消 |
| 地图 | 坐标、目标类别、等级、军队在途路线 | 平移、缩放、定位基地、坐标搜索、收藏 |
| 目标详情 | 已知守军、矿量、采率、保护与占用状态 | 侦察与出兵分开；无法获取的信息显示未知 |
| 行军面板 | 阶段、归属、兵力、货物、剩余时间 | 召回时显示返回时间，禁止把已采当已到账 |
| 战斗播放 | 当前轮、六格存活数量、伤害与命中事件 | 1 倍、2 倍、4 倍与跳过，查看事件，不参与结算 |
| 战报 | 投入、幸存、待修、永久损失、资源、关键伤害 | 重放、展开日志、跳到修理，同一记录不会再给奖励 |
| 修理 | 可修量、每型水晶费用和时间 | 数量、最大可修、提交、取消未完成部分 |
| 设置与存档 | 当前档位、保存时间、规则版本 | 导出、临时导入、备份恢复、音量、速度与清档 |

## 六格编队布局

在竖屏中，敌军预览位于上方，我军可编辑六格在下方。格子明确标 1 至 6，前后排使用文字标注；玩家无需依靠背景朝向猜测。点击某格打开型号与数量面板，设置后剩余库存立刻更新。

满编按钮只尽量填充可出战兵力。提示“按当前库存生成”，不提示“最优阵容”。遇到目标变化，保留编辑结果并重新显示侦察提示，避免全部清空输入。

## 消费与失败反馈

费用确认统一把取消放次要位置、确认放主要位置，文字写明动作，例如“消耗 3 水晶侦察”或“消耗 10 金币完成生产”。迁城不从一次点击地图直接执行。相关设计由玩家误消费投诉启发，不表示已复核原版每个按钮位置。[玩家评价 S18](https://www.taptap.cn/app/35038/review)。

操作失败不使用一串技术错误码。界面解释“还缺 120 铅矿”“科研中心需要 6 级”“部队正在返回，预计 30 秒后可用”。等待恢复进度时明确显示状态，避免重复点按钮。

## 视觉与声音目标

建议采用 2D 等距基地、军绿色和钢灰色面板、清晰的工业资源图标与写实倾向的战车剪影。坦克、歼击车、火炮和火箭车在炮塔、车体和武器轮廓上区分；不用颜色作为唯一分类方式。

建议先绘制第一代四类战车、基础建筑和关键 UI，第二、三代通过原创轮廓变体扩展。战报使用炮口闪光、炮弹轨迹、爆炸和数量下降表达伤害，不需要真实物理模拟每辆车。画面上一个战车图标代表一组数量型部队。

音乐与声音以基地环境、队列完成、出征、四类发射、爆炸、胜负和修理为基本集。静音时所有关键信息仍通过 UI 呈现。

## 可用性验收

在 390 乘 844 上无需横向滚动即可编辑六格、确认总成本、召回行军并看战损。PC 的 1280 乘 720 可以同时看主场景和一个详情面板。字号和按钮可由主题统一放大；拖动编队之外还要有点击交换方式。

这些是待实现的界面验收要求，尚无原型截图或完成的视觉 QA。
