三、规则与存档
新增可选 vip 扩展（version、paidGold、lastDaily）与 jobBacklog。
原 jobs.building/research/production/repair 保留；额外建设位用 building:2–7。
旧档没有 VIP 字段即为 V0。新文件仍执行完整结构、容量、唯一序号、兵力守恒校验。
每笔订单下单支付资源，改装同时预留原车/核心；取消未开工项退还全部，取消活动批次
退还未完成部分。活动批次结束/取消后，最早同类等待项在该时刻开工，离线同样执行。
加速仅完成指定 seq 项目，不能把随后自动接班的队列一并免费完成。
同一建筑或科技不可重复排队，不允许绕过前置条件提前预约未来等级。
VIP 速度与科技在下单时快照，不动态缩短既有任务；行军在出发时固定速度。
模拟充值通过带 root 授权的规则接口，原子写盘，重复命令 ID 不重复发币。
密码使用 scrypt 随机盐散列，本机独立文件，20 分钟会话；5 次错误后暂停 1 分钟。
root 初始密码和入口说明见 native/PLAYER_GUIDE.txt / 发布包 README.txt。
这是离线管理工具，本机用户能够访问并修改自己的文件，不宣称防修改或付费安全。

四、预计时间
所有预览与执行共用 core/vip.ts 和 arsenal.ts 的公式，避免客户端另写计算规则。
建设：基础时长 / (1 + 建设科技×5%)，向上取整到毫秒。
生产：基础单辆时长 / (1 + 生产科技×5% + VIP生产速度)，改装用 60% 基础并替换 VIP 改装速度。
科研：30 秒×(当前科技等级+1) / (1 + VIP科研速度)。
队列预计完成 = 当前批次剩余 + 在前等待批次时长 + 新批次时长。
采矿：两段行军 + min(出发运力,当前矿储) / 采集率。前瞻数值按无战损估算；
实时守军、其他同时采矿部队、召回会改变结果，界面明确标识“预计”。
已有远征展示本段剩余和预计回城；VIP 提高至 8 支后仍可分页浏览/召回每支。

五、战役与美术
战役错误根因：Godot JSON 中关卡编号为浮点数，旧客户端直接用整数 in Array 查找失败。
现在规则层提供 stageStatus.cleared/unlocked 布尔值，界面显示和操作权限共享同一依据。
旧存档已有 cleared 无需改写；演习仍不计进度，提示明确。
四类七阶通过底盘长度、装甲、炮塔、单双炮、发射器数量和配色建立形体差异。
库存显示尺寸因子 0.53/0.61/0.69/0.77/0.85/0.93/1.0；战斗目标宽度
110/130/150/171/191/211/232，另按高度限制防止重叠。
仓库与战斗使用同一组 28 车型、56 双向精灵；每个炮口重新标定，弹道从炮口沿主炮出射。
新增 16 帧击毁爆炸、8 个双向兵种残骸，叠加碎片运动、冲击环、火星；暂停共用战斗时钟。
战斗结束前等待最后一次击毁动画结束；跳过直接显示残骸，重播重新触发，数值结算不重复。
素材、完整提示词与来源路径：native/assets/manifest.json 中 v06 字段。
制作模式：内置 imagegen，未用 Python 修改图片；Python 仅读透明通道生成数值切片边界。
