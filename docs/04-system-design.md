# 坦克风云经典版系统设计

本文件是复刻建议。名称借用公开玩法的通用概念，数量、上限、状态、退费和离线行为均按本项目规则定义。原版无法确定的部分参见待验证清单。

## 建筑与基地

| 建筑 | 职责 | 前置与效果 | 队列 |
| --- | --- | --- | --- |
| 指挥中心 | 基地等级与土地开放 | 定义其他建筑等级上限；具体土地数量放配置 | 建筑 |
| 科研中心 | 科技解锁 | 中心等级与声望共同检验科技前置 | 建筑、研究独立 |
| 坦克工厂 | 战车解锁和生产 | 工厂等级控制型号，生产中可同时升级工厂 | 建筑、生产独立 |
| 改装工厂 | 低代战车转为高代 | P1，扣旧兵与差额资源，过程禁止旧兵出战 | 改装独立 |
| 仓库 | 资源容量及保护额度 | 容量与保护量分开；保护不增加产率 | 建筑 |
| 铁矿、油井、铅矿、钛矿、水晶矿 | 周期产出 | 产量、容量、格数由配置决定 | 建筑 |
| 修理入口 | 伤残恢复 | M1 由基地服务提供，不额外强制建实体修理厂 | 修理 |

早期记录的指挥中心上限关系由 S06/S05 支持；上述建筑并发行为属于设计建议。[S06](https://news.4399.com/gonglue/tkfy/xinde/m/370500.html)。

升级时依次推进世界到当前时刻、检查前置、验证资源和空队列、扣费并写入任务。到期后增加等级并更新效果。升级中旧等级继续生效；完成瞬间切换新产率或容量。M1 不允许取消建筑与研究，避免未设计的退款路径；生产和修理可取消尚未完成的数量，规则见下文。

## 资源账本

每种资源保存余额、容量、保护额度和小数余量。账本记录来源或去向：自产、关卡、任务、采矿、掠夺、建造、科技、生产、修理和侦察。钱包中的资源与行军携带资源分开。

建议的容量政策：自产到容量停止；回城、关卡和任务可使余额超过容量，不丢弃已获得资产；超额期间自产为零，界面提示。保护额度始终只保护钱包中 min(余额, 保护量) 的部分。在途货物无仓库保护。此政策需保持全局一致，不能在不同界面静默截断。

## 科技和技能

角色科技包含五类产率、四类攻击、四类生命、建筑速度、容量保护、战斗经验与行军速度。这个分类可由 2014 年资料核对，具体计算函数由本项目确定。[S07](https://news.4399.com/gonglue/tkfy/xinde/m/370620.html)。

M1 先提供产率、攻击、生命、建筑速度、载重与行军速度的少量等级。P1 再扩展命中、闪避、暴击、装甲及军团科技。所有加成通过统一 modifier 记录，包含属性、目标类型、加成组、来源和生效时刻。

同组百分比先相加，不同组再相乘。所有速度换算为 baseDuration / (1 + speedBonus)，不把每级 5% 速度误写成线性减去 5% 用时。是否符合原版仍待验证。

## 指挥官

| 字段 | 本项目定义 | 状态与限制 |
| --- | --- | --- |
| 等级与经验 | 完成任务及战斗累积 | 经验阈值是配置；可能一次跨多级 |
| 统率等级 | 每格带兵的容量来源 | M1 确定升级，消耗统率书，不采用未知成功率 |
| 声望等级 | 科技上限之一 | 与科技中心等级分别验证 |
| 军衔 | P1 的日常授勋成长 | 独立升级和每日领取状态 |
| 荣誉 | 真人 PVP 的战绩量 | NPC 战不产生“真人荣誉”，M1 默认不用该排行 |
| 展示战力 | 最强可组成编队的估计 | 单独统计库存价值；不能把全部库存加总当战斗实力 |

统率、声望与展示战力的历史角色由早期属性攻略说明；精确每级表待验证。[S08](https://news.4399.com/gonglue/tkfy/xinde/m/370587.html)。

M1 的每格上限是 20 + 5 乘 (统率等级 - 1)。该式自拟，不声称是原版。每格无兵种混合，同型号可跨格分配。编队预设只保存期望型号和数量，不锁库存；只有出兵会把实际数量从可用库存移入行军容器。

## 生产与修理

生产任务保存型号、原定数量、已完成数量、单辆时长和逐辆成本。提交时全额扣费，逐辆到期入可用库存。取消时退未完成数量的原始单位成本；正在制造的未完成一辆也取消，不保留部分进度，规则在 UI 中明确。已完成的兵不回退。相同费用只退一次。

修理先将待修数量移入修理任务，扣费用，逐辆回库。取消未完成部分后，这些兵回待修池并退相应水晶。伤残部队不能通过存档导入直接变成可用兵。战损率见战斗设计。

任务速度在提交时快照锁定；未来科技不改变已提交任务耗时。队列里尚未开始的订单，在真正开始时才快照时长。M1 简化为每类一个活动任务，未来增加等待队列时遵守上述区分。

## 行军与地图

~~~mermaid
stateDiagram-v2
    [*] --> Outbound: 预留部队并出发
    Outbound --> Resolving: 到达目标
    Outbound --> Returning: 提前召回
    Resolving --> Gathering: 胜利且目标为矿
    Resolving --> Returning: 掠夺成功或战败有幸存兵
    Resolving --> Lost: 全灭
    Gathering --> Returning: 满载 耗尽 召回或被击败
    Returning --> Completed: 到家归还部队和货物
    Lost --> [*]
    Completed --> [*]
~~~

矿点存储坐标、等级、资源种类、剩余量、守军及当前占用者。到达时重新读取真实目标；侦察结果不能锁住敌方状态。占领胜利后开始采集，不立即发全部资源。矿耗尽后触发回程，资源不会凭一次刷新重复出现。

两队同时到达时以事件排序决定先后；后一队根据更新后的占用者发起战斗。M1 若尚未实现矿上 PVP，NPC 不攻击已占矿，UI 必须声明当前模式；M2 才开启真人争夺。NPC 采矿与玩家使用相同状态机。

召回出发行军的回程距离按已走比例计算。采矿召回则携带已采量从矿点返回。回程状态不允许再次召回。到达与召回同一时刻时先结算到达事件再处理命令，因此召回的是刚形成的采集或回程状态。

## 关卡与任务

教学关卡分为“数量”“单体与范围”“兵种”“布阵”“侦察”“运输”和“战损恢复”。每关保存独立守军配置、解锁条件、重复收益、首通奖励和战损政策。关卡之间不借用世界矿点的所有权状态。

任务用领域事件推动进度，例如 BuildingUpgraded、UnitProduced、BattleSettled、MarchReturned。读 UI 不触发奖励。累计升级任务采用达到等级的条件，避免先升级后接任务无法完成。领取通过原子状态未领取到已领取的变化完成。

## 军团与后续世界

P2 军团至少包含成员、角色、加入审核、捐献、共享科技、聊天与协防日志。成员离团后失去军团属性，仅影响未来创建的战斗快照；在途行动的军团属性按战斗创建时重新获取。协防总量、出兵权和退团后的驻防返程必须单独设计。

本轮只确定模块边界，尚不宣称军团战、区域战和跨服战已经获得详细原版规则。首版留下 legionId 与协防扩展接口，先让单人核心完整。
