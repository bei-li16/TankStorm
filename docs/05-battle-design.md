# 坦克风云六格战斗详细设计

2026-10-02 / v0.7 已按官网原有攻击模式更新坦克横排，并移除自拟火箭 35% 折扣。详见 [本轮来源与验证](18-v07-combat-and-presentation.txt)。

本文件定义一个可以直接实现和验证的原型战斗器。六格、四类兵种和战前编队来自公开玩法；选敌、公式、随机数、回合顺序、加成和伤残比例都是**设计建议**。不能以本文件宣称已恢复原游戏内部算法。

## 原版证据与边界

官网玩家说明给出前排 123、后排 456，描述命中与闪避、暴击与装甲相对作用，并出现 150% 暴击和 40 回合防守胜的说法。它是 2016 年材料，不能确定早期同规则。[词缀说明 S14](https://tk.rayjoy.com/tank/game_psp/2016/1024/185.html)。

两篇 2014 年记录给出部分 125% 与 80% 克制关系，交叉核对结果一致，但未形成每个格子的完整攻击算法。下表没有描述的关系不能直接依据循环对称补齐。[战车相克表 S20](https://news.4399.com/gonglue/tkfy/xinde/m/370619.html)，[发行期指南 S05](https://news.17173.com/content/03312014/114231772.shtml)。

| --- | --- | --- | --- |
| 坦克 | 火箭车 | 1.25 | 使用 12500 基点 |
| 歼击车 | 坦克 | 1.25 | 使用 12500 基点 |

克制矩阵是有向矩阵。例如不能仅凭坦克对火箭 1.25 就确定火箭对坦克为 0.80。官网 [原有攻击模式](https://tk.rayjoy.com/wap.php?action=article&id=95) 明确了四类基础范围；具体空位选敌、暴击倍率及模式差异仍需继续核对 Q01 至 Q07。

## 输入输出契约

BattleInput 包含 battleId、rulesetId、rulesetHash、seed、mode、双方编号、六格型号与数量、属性快照、先手值和战损政策。战斗器不读钱包、数据库、系统时间或 UI。

BattleResult 返回胜负、回合数、双方各型号初始量与幸存量、待修量、永久损失、事件流、随机数最终状态和 resultHash。关卡奖励与掠夺结果由世界应用层计算，战斗器不直接往账号发资源。

重复调用同一 BattleInput 必须产生相同输出。播完、快进、跳过和重复观看均仅消费事件流。计算完成但界面中断，恢复后仍使用已保存结果，不重新掷骰。

## 六格与数量

逻辑坐标固定为三列两排；屏幕上的朝向是显示层转换。

~~~text
敌方阵型                       我方阵型
后排  4  5  6                 前排  1  2  3
前排  1  2  3                 后排  4  5  6
~~~

同一列是 1 与 4、2 与 5、3 与 6。显示层不得使用镜像坐标来改写逻辑 slotId。格子保存 unitId、initialCount、aliveCount、hpPerUnit、totalHp 及有效属性。

初始 totalHp = initialCount 乘 hpPerUnit。受伤后 totalHp = max(0, totalHp - damage)，aliveCount = ceil(totalHp / hpPerUnit)。剩余一辆不足满血的车辆仍贡献一辆的攻击。部分生命只在本次战斗内保留；结算后幸存车辆恢复完整生命。此抽象是建议，可以后续改为逐辆模型，但不能重复扣车。

## 攻击顺序

原型以 initiative 更高的一方为先手，平值由进攻方先手。M1 不堆叠将领先手系统，默认双方均为零；这意味着默认进攻方先手属于本项目规则。

每轮的队列是先手方格 1、后手方格 1、先手方格 2、后手方格 2，依次到格 6。已被击毁的格跳过。每次攻击后检测一方是否全灭，并立即结束。第 40 轮仍有双方存活时记为防守胜；训练模式可另设平局，但必须用独立 mode 配置。

这套交替顺序便于产生“提前削掉敌军数量”的作用。它不是已确认的原版回合顺序，须用早期战报校准。

## 四兵种的原型职责

| 类型 | 攻击模式 | 目标选择与范围 | 建议团队效果 |
| --- | --- | --- | --- |
| 坦克 tank | front_row | 取敌方存活前排全部目标；前排全空再打后排 | 存活时全军攻击加 5% |
| 歼击车 tank_destroyer | single_front | 取最靠前的存活编号，基础单体伤害更高 | 全军暴击概率加 5 个百分点 |
| 自行火炮 spg | column | 以上述首个目标为锚，命中该列所有存活格 | 全军受 piercing 伤害减 10% |
| 火箭车 rocket | all_alive | 攻击全部存活敌格，无额外群攻折扣 | 全军受 rocket 伤害减 10% |

团队效果的存在方向有官网玩家资料支持，具体百分比、叠加和存活条件是自拟。[排兵布阵 S13](https://tk.rayjoy.com/tank/game_psp/tactics/149.html)。

同类团队效果不因多个格或单格车辆数量重复叠加，取最高一项。每次行动开始依据仍存活的兵种重算效果；某类最后一格死亡，其效果从下一次行动起失效。允许少量兵提供效果，是否限制需依平衡测试决定；不能直接假定原作有最小数量门槛。

自行火炮在确定锚点后同时固定本次目标列表；不能击毁一个目标后跳到别列。火箭车目标也在攻击开始时固定。对每个目标分别计算克制、命中、暴击、减伤。群攻不存在溢出转伤，空位不受伤害。

## 伤害与随机数

使用 10000 为一倍的整数基点，roundingPolicy 为“乘完整分子后统一向下取整”。中间乘积使用 BigInt 或等价宽整数，避免 JavaScript 安全整数溢出；公开数值仍为非负安全整数。

~~~text
hitBps = clamp(9500 + source.accuracyBps - target.evasionBps, 1000, 10000)
critBps = clamp(1000 + source.critBps + teamCritBps - target.armorBps, 0, 7500)

base = aliveCount * unitAttack
damage = floor(base * attackBonus * matchup * pattern * crit * reduction / 10000^5)
damage = max(1, damage)  // 仅在命中且目标仍存活时
~~~

unitAttack 是配置基础攻击，不预先叠加攻击科技；attackBonus 再包含同组叠加后的科技、技能及团队攻击，避免重复加成。hpPerUnit 则在战斗开始时按基础生命与生命加成计算并向下取整。matchup 为有向克制矩阵。pattern 四类均为 10000，范围攻击不额外打折。crit 普通为 10000，暴击为 15000。reduction 是按伤害类型匹配后的团队减伤系数。M1 不加入随机伤害浮动、连击或击破属性。

本原型中“装甲”降低对方暴击概率，不能又当作生命或直接减伤使用。15000 暴击倍率是暂选值，早期 2.0 与晚期 1.5 的冲突仍未解决。准确率与暴击的基础值都是自拟。

随机数使用 xorshift32：种子范围 1 至 4294967295，零种子拒绝。按无符号 32 位执行 x ^= x << 13；x ^= x >>> 17；x ^= x << 5；最后转 uint32。rollBps = floor(uint32 * 10000 / 4294967296)。每个目标固定消耗两次随机数，分别是命中和暴击，即使未命中也保留暴击抽样。按目标 slotId 升序消耗随机数，避免 Map 遍历顺序影响结果。

命中成立当 hitRoll < hitBps；暴击成立当 critRoll < critBps 且命中。所有随机数从输入 seed 生成，外部不能调用 Math.random。若以后更换随机算法，必须更换 rulesetId，旧战报仍保留旧解释器。

## 战损与修理

建议 M1 的非训练战斗统一采用：lost = initialCount - survivingCount；repairable = floor(lost 乘 0.70)；destroyed = lost - repairable。整数余数归永久损失。70% 不是查得的原版比例，也不是对任何原版模式的推断。

训练只计算模拟伤亡，实际库存、修理池与永久损失统计均不改变；正式关卡与地图都有上述战损。正式关卡在一个事务内预留兵力、结算、把幸存兵归还可用库存并把待修兵放入伤残池，不产生回程。世界战斗的待修兵也在结算时进入伤残池，但幸存兵留在行军容器到回城才可用。世界全灭时关闭行军并立即释放队列；待修池仍保留应得数量。一个 unitId 跨格先汇总 lost 后取整，避免拆成小格改变修复率。

对于矿上防守失败：先把被击败采集队的资源采集推进到战斗时刻，再按幸存兵新载重截断货物；超出载重部分作为败军丢失，M1 不额外复制给矿池或进攻方。进攻方只继续采集矿中剩余资源。该政策是最小实现，若后续设计战利品夺取，必须单独做数量守恒与交接。

## 战报事件

事件按 seq 递增：BattleStarted、RoundStarted、AttackResolved、AuraChanged、StackDestroyed、BattleEnded。AttackResolved 包括源格、目标格、攻击前数量、伤害类型、命中、暴击、最终伤害、目标前后 HP、各倍率和本次随机序号。

战报摘要同时展示战力估计、各型投入、幸存、待修、永久损失与奖励。详情允许看“哪次攻击造成多少损失”；不要只显示输赢和一个不可解释的总战力。

## 必须验证的场景

| 场景 | 应有结果 |
| --- | --- |
| 同输入同种子多次结算 | 完全相同事件流和哈希 |
| 后手格在行动前死亡 | 本轮跳过，不允许尸体开火 |
| 前排为空 | 单体选敌转后排，无空引用 |
| 列攻只有一个存活目标 | 只打该目标，不补打其他列 |
| 群攻同时击毁多个格 | 每个目标有独立日志，整体只结算一次 |
| 同类型分成多个格 | 团队效果不重复叠加 |
| 伤害不足一辆生命 | 更新 HP，数量用 ceil 保持一致 |
| 伤害超过全军生命 | HP 归零，无负库存和溢出伤害转移 |
| 每种兵损合计 3 辆 | 待修 2、永久 1，不因格子划分改变 |
| 跳过动画、重复看战报 | 不再次扣兵、不再次发奖 |

精确历史规则只能在获得原版战报或可使用的早期客户端后替换。替换时保留以上契约与守恒测试，以便比较两套规则。

新战报使用 `classic-combat-v0.7`，存档容器规则标识保留以兼容旧档；历史战报使用其已有事件回放，不重新结算。
