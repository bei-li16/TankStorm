# 坦克风云经典版产品需求

本需求将用户选择的早期经典体验转化成可交付的个人复刻项目。2026-10-02 用户明确指定 Windows 原生游戏，并要求保障完整单机体验、不考虑多人联机。当前平台和验收以 [Windows 版记录](14-native-windows.md) 为准。下表保留最初阶段划分用于追溯，M2 已移出当前开发范围。

## 产品目标与首版范围

玩家可以从小基地起步，生产部队、升级科技、调整六格、挑战关卡、派队采矿，经历战损并重建军力；退出后重新进入仍保留世界进度。

M0 是战斗与经济验证工具。M1 是完整单人可玩版本。最终产品面向 Windows 桌面，支持完全离线、保存和继续游玩。最初的浏览器和移动竖屏建议已被替代。M2 的多人设计只作为历史资料保留。

| 阶段 | 建议内容 | 完成定义 |
| --- | --- | --- |
| M0 | 四兵种、六格、伤害日志、资源与队列模拟 | 相同输入重放一致，能解释一次输赢 |
| M1 | 单人基地、五资源、12 个原型单位、20 个等级、12 个教学关卡、32 乘 32 地图、NPC 基地 | 完成从造兵到采矿回城及修理的闭环，存档恢复一致 |
| M2（移出范围） | 原设想：服务端权威、真人世界、军团与协防 | 当前不开发、不作为单机交付条件 |
| 扩展 | 历史数据还原、更多车辆和关卡、可选配件 | 每项独立评估，不要求一次纳入全部后期系统 |

首版不包含真实支付、广告 SDK、无限滚动活动、跨服服务器或大量卡池。游戏内金币仍可用于加速体验，但通过任务获得；这是一项复刻模式设计。

P0 为 M1 必须满足；P1 为 M1 后补齐的单机扩展；P2 为已移出范围的历史多人方案。当前不把 P1、P2 全表都宣称为已实现。

## 非功能需求

| ID | 建议目标 | 验证条件 |
| --- | --- | --- |
| N01 | 资产守恒与事务一致 | 任意失败命令、重试或崩溃不造成重复产兵或奖励 |
| N02 | 确定性 | 同规则包、快照、种子生成相同事件流与结果哈希 |
| N03 | 可维护 | 规则配置有来源状态、版本、字段范围，界面不持有伤害逻辑 |
| N04 | 可访问 | 数量和费用不用纯颜色表达；表单支持键盘与清晰文本 |
| N05 | 性能预算 | 基准机上 60 FPS 为目标，最低持续 30 FPS；12 格战斗无播放卡死 |
| N06 | 响应预算 | 参考规模下命令处理 P95 小于 100 ms，读档小于 3 s；需实现后实测 |
| N07 | 兼容 | Windows x64 桌面；1280×720 及 1440×810 等比例布局；移动竖屏不再是交付目标 |
| N08 | 可恢复 | 24 小时离线推进、生产中断恢复、导出导入均无资产丢失 |
| N09 | 本地隐私 | 单人档不要求注册；错误日志默认不含账号凭证或完整存档 |

当前 M0 规则验证已完成，M1 基地—生产—编队—战斗—采运—修理—存档主链通过验证。v0.3 增加长期世界补给和可选休整，实际记录见 [Windows 验收](14-native-windows.md)。图鉴和预设已实现；目标收藏、战报筛选、迁城和主动 NPC 扩张尚未实现，不能把原始需求表全部视为已完成。

## 体验验收脚本

从新档开始，玩家能看到下一步建设目标，升级工厂并生产战车。玩家调整阵容通过前两个教学关，侦察附近矿点，观察出发与返回，拿到可见资源收益。随后挑战有风险的敌军，查看损失与原因，修复部队再尝试。退出后重新进入，上述基地、库存、行军和奖励状态保持一致。

这个流程必须同时覆盖“造得出来”“配得明白”“打得有结果”“损失可理解”“下次还能继续”。军团相关需求单独在 M2 验收，不能用 NPC 通过单人验收来宣称恢复了多人社交。
