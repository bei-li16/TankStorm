# 坦克风云经典版玩法分析

经典体验来自经营一个不断积累、派遣和消耗部队的基地。下面先记录能由资料支撑的系统，再解释其作用；解释属于设计分析，不宣称代表原开发者的意图。

## 核心循环

下图是本项目对公开玩法的抽象，用来划分模块。

~~~mermaid
flowchart LR
    A[资源与任务奖励] --> B[建筑与科技]
    B --> C[解锁并生产战车]
    C --> D[库存与六格编队]
    D --> E[关卡和世界行动]
    E --> F[战损 修理与运输]
    F --> A
    G[统率和声望] --> B
    G --> D
    E --> G
    H[军团与其他玩家] --> E
~~~

**分析：**小循环提供“下一批坦克完成”的反馈，中循环提供“解锁下一代兵种”的目标，大循环由地图局势和战友关系推动。只做战斗画面会缺少资产积累的意义，只做挂机资源又缺少投入军队的风险。

## 六格的含义

六格应当各自持有一个兵种定义和数量，不将画面上一辆坦克理解为库存中的唯一对象。同型号可以出现在多个格子，出兵数量受库存和带兵上限共同约束。少量诱饵、主力输出和兵种加成可以共存，这是配置资源的决策。

与角色养成的差异是本项目的建模结论：战车库存会被生产、预留、摧毁和修复，因此需要数量守恒；角色技能式的对象系统不能直接替代它。

## 游戏性来源

| 决策 | 对应约束 | 后续实现需要提供的信息 |
| --- | --- | --- |
| 先发展经济还是兵力 | 资源与生产队列争用 | 成本、时间、产量和目标解锁 |
| 主练哪类战车 | 科技投入与克制 | 兵种作用和可理解的战报 |
| 哪个格子放主力 | 攻击范围和先后顺序 | 阵位编号、攻击预览和数量 |
| 派多少兵采矿 | 行军队列、载重与基地留守 | 距离、守军、预计运输量 |
| 是否挑战更强目标 | 兵损与修理成本 | 侦察时刻、风险和历史损失 |
| 是否召回 | 收益尚在路上，其他行动等待 | 行军状态、已采量和回程时间 |
| 与谁合作 | 真实玩家行为 | 后续军团、战报共享、驻防 |

以上是分析与界面需求，不是对原版 UI 字段的完整抄录。

## 玩家体验中的张力

早期玩家记录认为部分时期火箭车收益过高，并采用火箭前排、少量诱饵的阵容。这说明名义克制不足以保证实际平衡；伤害范围、出手顺序、成本和战损共同决定收益。[早期排兵心得 S17](https://www.9game.cn/tkfyol/186385.html)。

**设计建议：**先让四兵种各有明确场景，再调数值。建议允许“历史倾向”规则包与“原型平衡”规则包分别存在，但只有获得可靠数据后才能把某个包标成历史版本。当前只提供原型平衡包。

官网玩家心得中也存在通过反复取消、轮换强化来“提高成功率”的说法。这些属于玩家信念，没有可验证的概率证据；不做成程序规则。[综合心得 S16](https://tk.rayjoy.com/tank/game_psp/zonghe/150.html)。

## 经典版边界

保留基地、五资源、科技、统率、生产库存、六格自动战斗、关卡、地图资源点、运输、战损与战报。军衔、声望、技能保留轻量模型，避免把基础成长压缩成唯一战力数字。

将领招募与授勋、将领装备、异星科技、超级武器、战机、装甲矩阵、跨服竞赛等进入扩展目录，首版不接入。2016 年资料已包含多种后期养成，不能据其发布时间认定它们在 2013 年首发时存在。[官方资料索引](https://tk.rayjoy.com/tank/game_data/index.html)。

“早期经典版”在本项目表示玩法范围，而非已确定的某个安装包版本。原版界面比例、具体战车名、成本、解锁表和全部关卡配置需要继续采样，见待验证文档。
