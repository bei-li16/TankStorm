# 经典战线首版验收记录

本记录对应 2026 年 10 月 2 日的单人首版。自动化结果见 `artifacts/test-results.json`，性能结果见 `artifacts/core-benchmark.json` 与 `artifacts/browser-performance.json`。本文仅把实际执行过的验证记为通过，原研究文档中的未来多人测试仍未执行。

## 自动化验证

80 项测试全部通过，失败 0 项。测试由 Vitest 在本机执行；TypeScript、代码格式和 Vite 生产构建通过。安装依赖后的 npm audit 未发现已知漏洞。

| 验证范围 | 已验证行为 |
| --- | --- |
| 新档和地图 | 相同种子生成相同世界；100 个目标位置不重叠；五种资源都有矿点 |
| 费用与队列 | 失败不扣费；升级跨时间段使用正确产率；逐辆生产；部分完成后的取消、退款和修复 |
| 阵容与库存 | 同型号跨格不能超库存；统率按单格限制；预设不锁库存；出征部队不能重复使用 |
| 战斗 | 固定种子重放一致；前排选敌、纵列与群攻；完整乘积后取整；同兵种汇总后算修复比例 |
| 战斗奖励 | 首通只发一次；重复战役按重复奖励发放；同命令重试不再次结算；演习不消耗战车 |
| 成长内容 | 12 种战车都可生产；指挥中心可完成全部 20 级；成熟部队可以打通全部 12 关 |
| 侦察和运输 | 旧情报不覆盖实际守军；出征属性锁定；载重和矿储量限制；提前召回；到家只入库一次 |
| NPC 和冲突 | 保护量不可被抢；货物受载重限制；同时抵达同一矿点按顺序处理；矿点耗尽返航 |
| 时间 | 北京时间日切；系统时钟后退不倒扣；24 小时一次推进与分步推进一致 |
| 存档 | 导出导入一致；格式错误、规则未知、结构损坏、非法引用或资产不守恒都拒绝 |
| 并发和恢复 | fake-indexeddb 中两个同 revision 写入只有一个提交；重试幂等；失败事务回滚；恢复前次备份 |
| 长时间模拟 | 400 次确定性操作与时间推进，每次成功后检查守恒，每次失败后检查原状态没有变化 |

“十二关可通关”测试使用已发展部队，证明关卡结果可达，不表示已验证普通玩家从零达到终局的时长或长期平衡。

## 浏览器实际操作

通过 Codex 内置浏览器操作运行中的应用，使用 1280 × 720 与 390 × 844 两种视口。以下操作实际发生在专门的验收档案中：

1. 领取新手补给，核对已领取状态；升级指挥中心并观察等级变为 2。
2. 下单生产 10 辆轻型坦克，观察队列与完成后的 50 辆待命总数。
3. 自动填充并保存编队；在手机表单输入超限 999，确认弹窗内显示错误；用 Tab、Enter 修正并保存。
4. 正式通过前三个战役，跳过回放并核对战报。第三关出现坦克损失 5、可修复 3、永久损失 2，以及火炮损失 3、可修复 2、永久损失 1。
5. 将 3 辆受损坦克送入修复队列，随后刷新页面仍可读取已完成修复后的进度。
6. 侦察 `(17,16)` 铁矿、出征并开始采集；手机端从“基地动态”召回，观察 2 份已采货物随部队返航，并在基地日志看到回城入库。
7. 修改测试指挥官名称，实际下载 JSON 存档；通过文件选择器重新导入，列表保留原档并新增独立档案。
8. 刷新页面，核对建筑、部队、关卡和角色进度保持；首次启动页面显示名字与世界种子输入项。
9. 新建独立档案，确认初始建筑 1 级、40 辆部队和未通关状态。

实际导出文件约 98 KB。浏览器下载事件监听没有返回，但磁盘中存在下载文件，且其后通过文件选择器成功导入；因此导出结果通过实际文件与导入结果确认。

操作中发现并修复的问题包括：小屏原本无法操作被隐藏的队列、弹窗遮住全局错误提示、小屏隐藏导航仍可获得键盘焦点、地图生成规则漏掉水晶矿、改名后存档列表显示旧名。修复后补充了回归检查或自动化用例。最终格式化时还发现开发服务器短暂缓存写入中的空模块，现已启用文件写入稳定等待；服务器重启及页面重新加载后恢复正常，生产构建未出现该问题。

## 性能与范围

基准机为 Windows、Intel Core i5-8400 @ 2.80 GHz、Node.js 24.14.1。

- 核心命令：已有 100 场战报的档案，执行 40 次命令，P95 约 20.14 ms，最大约 20.60 ms。包含核心校验，不含浏览器渲染、Worker 传输与 IndexedDB I/O。
- 浏览器已有档案的本地加载：两次正常导航的界面准备约 265 ms 与 424 ms。基地至战役切换采样 240 帧，平均 58.53 FPS，P95 帧间隔 16.8 ms，最大单帧间隔 66.6 ms；战斗播放采样 240 帧，平均 59.50 FPS，P95 16.8 ms，最大 33.4 ms。缓存与开发模式会影响读数，不能替代冷启动或实体手机测量。原始日志中 77443 ms 是热更新后的页面存活时间，不作为启动数据；已让探针跨热更新保留采样标记。
- 计算和保存已移到 Worker。战斗面板采用历史事件流播放，暂停或切换速度不触发资产结算。
- 浏览器最终采样与场景标签以 `artifacts/browser-performance.json` 为准。此处的响应式验证采用浏览器视口模拟，未在实体 Android 或 iOS 设备上执行。

开发时可访问 `/?perf=1`，在控制台读取不包含玩家数据的加载和帧间隔采样；生产构建不启用该功能。
